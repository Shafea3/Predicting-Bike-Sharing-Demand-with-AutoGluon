# Predict Bike Sharing Demand with AutoGluon

End-to-end solution for the Kaggle "Bike Sharing Demand" competition using AutoGluon Tabular. The project guides you from data access to model training, feature engineering, hyperparameter tuning, and Kaggle submissions, all within a single notebook.

## Contents

- main_notebook.ipynb — main notebook with all steps and outputs
- bike-sharing-demand/ — data folder (train.csv, test.csv, sampleSubmission.csv)
- submission.csv — baseline submission generated by the notebook
- submission_new_features.csv — submission after adding features
- submission_new_hpo.csv — submission after HPO
- model_train_score.png — validation RMSE across runs
- model_test_score.png — Kaggle scores across submissions

## Dataset

Competition: https://www.kaggle.com/competitions/bike-sharing-demand

- Train file: `bike-sharing-demand/train.csv`
- Test file: `bike-sharing-demand/test.csv`
- Sample submission: `bike-sharing-demand/sampleSubmission.csv`

## Environment

- Python 3.8+ recommended
- AutoGluon Tabular
- macOS (zsh) / Linux compatible (paths may differ on Windows)

Install core dependencies:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -U pip setuptools wheel
pip install "mxnet<2.0.0" bokeh==2.0.1
pip install autogluon --no-cache-dir
```

If you run into memory issues on smaller machines, keep `--no-cache-dir` and consider reducing the AutoGluon time limits or HPO trials in the notebook.

## Kaggle API setup (do this once)

1. Create an API token in Kaggle: Account -> API -> Create New API Token.
2. Place the downloaded `kaggle.json` at:
   - macOS/Linux: `~/.kaggle/kaggle.json`
3. Restrict permissions:

```bash
chmod 600 ~/.kaggle/kaggle.json
```

Note: Avoid hard-coding your username/key in notebooks. If you already did, rotate your key in Kaggle and remove secrets from version control.

## How to run

1. Ensure data is present under a local folder (default expected):

   - `./bike-sharing-demand/train.csv`
   - `./bike-sharing-demand/test.csv`
   - `./bike-sharing-demand/sampleSubmission.csv`

2. Open the notebook (relative path): `project-template.ipynb`

3. Paths note: The notebook assumes the data lives under `./bike-sharing-demand`. Paths may differ on your machine—adjust file paths as needed.

4. Run cells top to bottom. The notebook covers:
   - Installing packages (if needed)
   - Loading train/test data with datetime parsing
   - Exploratory data analysis (histograms)
   - Feature engineering (extract hour, set season/weather as categorical)
   - Baseline training with AutoGluon
   - Predictions, clipping negatives to 0 (Kaggle requirement)
   - Preparing and saving submissions
   - Re-training with added features
   - Hyperparameter tuning (HPO)
   - Report plots (validation RMSE and Kaggle scores)

## Key settings used

- Label: `count`
- Ignored columns: `casual`, `registered`
- Metric: `root_mean_squared_error`
- Presets: `best_quality`
- Time limit: 600 seconds per training block
- HPO: random search (GBM, XGB, CAT, NN_TORCH) with 10 trials in this repo (adjustable)

The notebook also saves:

## Submitting to Kaggle

The notebook includes cells to submit via the Kaggle CLI, e.g.:

```bash
kaggle competitions submit -c bike-sharing-demand -f submission.csv -m "first raw submission"
```

Ensure your `kaggle` CLI is installed and authenticated with `kaggle.json` in place.

## Tips and troubleshooting

- If AutoGluon install fails, ensure you have a compatible MXNet version (`<2.0.0`) and enough disk/memory.
- If submissions are rejected, ensure all predicted `count` values are >= 0. The notebook clips negatives to 0.
- Paths may differ across machines; adjust file paths (or a small `DATA_DIR` variable) accordingly.
- To speed up: reduce `time_limit` and HPO `num_trials`.
